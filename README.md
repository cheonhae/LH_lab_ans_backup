## 2. 백업 투입 기준

- 다음 모듈 시작 시각이 되었는데 앞 모듈 산출물이 main에 없고, 남은 단계를 블록 안에 끝낼 수 없다고 판단될 때.
- 투입은 **막힌 레포에만** 함. 분반 전체에 일괄 투입하지 않음.
- 투입 전 교육생에게 알림: 백업은 같은 경로의 파일(특히 `CLAUDE.md`·`outputs/`)을 덮어씀. 교육생이 만든 앞 단계 결과는 이력에 남고, 필요하면 투입 PR을 **Revert**로 되돌릴 수 있음.
- 투입 후 교육생은 다음 모듈을 백업 산출물에서 시작함. 앞 모듈의 6점 단계(근거 대조·검산·정합 검사)는 백업 산출물을 대상으로 짧게라도 수행하게 함.

## 3. 투입 절차

1. 데스크톱 앱 Code → Cloud → 환경 `AX심화교육`에서 **이 강사 레포와 막힌 교육생 레포 2개**를 골라 세션을 엶(투입 작업 때만 레포 2개 세션을 씀).
2. 세션에 지시:
   ```
   instructor 레포의 backup/m3_start/ 안 파일을 교육생 레포의 같은 경로에 복사해 줘. 교육생 레포의 inputs/ 는 건드리지 마. 덮어쓰는 파일 목록을 먼저 보여 주고, 내가 확인하면 커밋해 줘. 커밋 메시지는 [운영] M3 시작 백업 투입으로 해 줘.
   ```
   (`m3_start`는 상황에 맞게 `m2_start`·`m4_start`로 바꿈. M5 구현이 안 되는 좌석은 `answer/m5/README_보조인력.md`의 '복사할 파일'만 같은 방식으로 넣고, 커밋 메시지는 `[운영] M5 결과물 투입`)
3. 덮어쓰는 파일 목록에 `inputs/`·`.claude/skills/hanbit-prd-interview/`가 없는지 확인 후 승인.
4. 교육생 레포 쪽 변경에서 **Create PR** → GitHub 웹 **Merge**(강사가 병합). main에서 `CLAUDE.md` 절 수와 `outputs/m*/` 파일을 확인.
5. 대체 경로: 레포 2개 세션이 안 되면 강사 PC에서 이 레포를 **Code → Download ZIP**으로 내려받아, 교육생 레포에 GitHub 웹으로 해당 파일을 올림(올리는 화면과 새 브랜치 + PR 선택지는 D-7 실측 결과대로). 커밋 메시지는 위와 같음.
6. 투입 기록: 운영 기록표에 좌석번호 · 투입 백업 · 시각 · PR 번호를 남김.

## 4. 하지 않는 것

- `answer/` 파일을 교육생 레포에 커밋하지 않음(`skill_completed/` 포함). M4 Skill 빈칸은 교육생이 채움.
- 교육생 레포의 `inputs/`를 고치지 않음.
- 함정 위치·기대값을 교육 화면에 띄우지 않음. 강사는 `_instructor/` 문서를 별도 화면·인쇄물로 봄.
