## 1. 프로젝트 개요 (왜)

- 해결하려는 문제: 누리 행복주택 2단지 모집공고가 두 번 정정(v2·v3)되면서, 민원대장의 '적용공고' 칸을 담당자가 손으로 적는다. 접수일과 맞지 않는 버전이 적힌 행이 섞여 있어, 버전별 민원 집계와 답변 문구가 틀어질 수 있다.
- 배경: M3에서 수치 대장(`ledger/ledger.csv`)을 단일 기준으로 정했다. 공고 게시일도 대장에 있으므로, 같은 기준으로 대장 칸을 맞춰 볼 수 있다.
- 기대 변화: 행을 눈으로 하나씩 보는 대신, 명령 한 줄로 '기준 공고와 다른 행' 목록과 사유를 받는다.

## 2. 사용자 분석 (누가)

- 주 사용자: 임대공급팀 민원대장 담당자(주간 민원 보고 전에 대장을 정리하는 사람)
- 쓰는 상황: 주간 민원 보고 초안을 쓰기 전, Claude Code 클라우드 세션에서 실행한다.
- 현재 방식과 한계: 엑셀 필터로 날짜를 나눠 보며 버전을 확인한다. 정정공고 게시일 당일 접수처럼 경계에 있는 행을 사람마다 다르게 본다.

## 3. 기능 요구사항 (무엇을)

- MVP(이번에 만드는 것, 1기능): **적용공고 대조** — 접수일로 그날 유효한 공고를 계산해 대장의 적용공고 칸과 대조하고, 다른 행을 사유와 함께 보여 준다.
  1. 대장의 공고 게시일(v1·v2·v3)을 읽어 접수일별 기준 공고를 정한다.
  2. 접수일 표기가 표준(YYYY-MM-DD)이 아니면 대조하지 않고 '접수일 확인 필요'로 따로 보여 준다.
  3. 일치·불일치·확인 필요 건수와 기준 공고별 건수를 요약하고, 행별 결과를 파일로 남긴다.
- 다음(이번에 만들지 않음): 미답변 민원의 답변 기한 확인, 주간 민원 보고 초안의 버전별 수치와 대조.

## 4. 비기능 요구사항 (어떻게)

- 데이터: 실제 자료는 넣지 않는다. 가상 표본 데이터로만 시험한다. 데이터를 외부로 보내지 않는다.
- 사용 환경: Claude Code 클라우드 세션, Python 표준 라이브러리만 쓴다(추가 설치 없음).
- 제약: 원본 CSV는 읽기만 한다. 결과 CSV는 UTF-8(BOM). 게시일은 대장 값만 쓰고 스크립트에 적어 넣지 않는다.
- 판단 경계: 어느 공고를 적용할지는 담당 검토 후 확정한다. 도구는 '기준과 다름'을 알려 줄 뿐이다.

## 5. 성공 지표 (성공)

- 판정할 수 있는 문장: **표본 15행을 넣으면 불일치 4건과 접수일 확인 필요 1건이 행 번호·사유와 함께 나오고, 나머지 10건은 일치로 나온다.**
- 경계: 정정공고 게시일 당일 접수는 새 공고로 본다. 빈 파일이면 '행이 없습니다'라고 안내한다.
- 넣은 검증 절차: 정합 검사(대장 = 단일 기준과 대조, M3).
