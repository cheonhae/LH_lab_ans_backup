# M5 인터뷰 기록 — 민원대장 적용공고 확인기 (모의 실행)

> `/hanbit-prd-interview` → 페이스 **코어** → 1~5단계. 단계마다 진행자 질문 하나, 교육생 답 한 줄을 요약했습니다. 진행자 문구는 실제 화면과 다를 수 있습니다.
> 출발점: 월요일 `docs/prd_memo.md` — "문제: 대장 적용공고 칸이 접수일과 안 맞는 행이 있다 / 쓰는 사람: 민원대장 담당 / 확인 방법: 다른 행 수가 손으로 센 값과 같은가"

| 단계 | 진행자 질문(요지) | 교육생 답(요지) | PRD에 들어간 곳 |
|---|---|---|---|
| 1 왜 | 어떤 불편을 줄이고 싶나요? | 정정공고가 두 번 나와서 대장 적용공고 칸이 접수일과 안 맞는 행이 섞인다. 버전별 집계가 틀어진다. | 1절 |
| 2 누가 | 누가, 언제 쓰나요? | 민원대장 담당자가 주간 민원 보고 전에 세션에서 실행한다. | 2절 |
| 3 무엇을 | 꼭 필요한 기능 하나는? | 접수일로 기준 공고를 계산해 대장 칸과 대조. 기한 확인은 다음으로 미룬다. → **MVP 1개** | 3절 |
| 4 어떻게 | 데이터는 어떻게 다루나요? | 실제 자료는 넣지 않는다. 가상 표본 데이터로만 시험한다. 데이터를 외부로 보내지 않는다. 게시일은 수치 대장에서 읽는다. | 4절 |
| 5 성공 | 무엇이 되면 성공인가요? (건너뛰지 않음) | 표본 15행 → 불일치 4건·확인 필요 1건이 행 번호·사유와 함께 나오고 나머지 10건은 일치. 게시일 당일은 새 공고. | 5절 |

- 정리 카드에서 바꾼 것: 3단계에서 진행자가 "답변 기한 확인도 넣을까요?"라고 물어, '다음' 기능으로 따로 적었습니다(팀 프로젝트에서 기능 B로 이어짐).
