# 수용 기준표 — 시연용 조(행정) 민원대장 확인기

> 작성: ④ 검증·데이터 담당 · 커밋 머리 `[팀-검증데이터]`
> 기준은 `prd/team_prd.md` 5절(성공 지표)에서 가져왔습니다. 기대값은 도구를 돌리기 전에 표본과 기준표를 보고 손으로 셌습니다.

## 1. 시험 조건

| 항목 | 내용 |
|---|---|
| 시험 대상 | main의 `scripts/main.py`(통합) · `scripts/notice_version.py` · `scripts/reply_deadline.py` |
| 표본 데이터 | `data/team_sample.csv` (20행, 가상 · 일부러 넣은 함정 1개) · 게시일 기준표 `data/notice_dates.csv` |
| 이식한 검증 규칙 | 수치·날짜는 기준표 한 곳만 쓴다(개인 CLAUDE.md 3절) · 비표준 표기는 지우지 않고 '확인 필요'로 따로(2절) |

## 2. 기대값 (도구를 돌리기 전에 계산)

| 항목 | 기대값 | 계산 근거(두 번째 방법) |
|---|---|---|
| 전체 행 · 접수일 확인 필요 | 20 · 1(T-12) | 표본을 열어 행을 세고, 접수일 칸이 YYYY-MM-DD가 아닌 행을 눈으로 찾음 |
| 기준 공고별 | v1 2 · v2 6 · v3 11 | 접수일을 게시일(10-05·10-26·11-04)과 비교해 손으로 분류, 게시일 당일은 새 공고 |
| 적용공고 불일치 | 4 (T-04·T-10·T-14·T-17) | 기록 칸과 손으로 분류한 기준 공고를 한 줄씩 대조 |
| 미답변 · 기한 지남 | 10 · 5 (T-02·T-05·T-07·T-09·T-11) | 접수·처리중 행의 접수일에 7일을 더해 2026-11-13보다 앞선 것을 셈, T-12 제외 |

## 3. 수용 기준

| # | 기준 | 입력(시험 방법) | 기대 | 1차 결과 | 교차 검증 결과 |
|---|---|---|---|---|---|
| AC1 | 표본을 넣으면 전체 행·확인 필요 수가 2절과 같다 | `python tests/run_acceptance.py` | 20행 · 1 | ☑ 통과 ☐ 수정 | ☑ 통과 ☐ 수정 |
| AC2 | 기능 A 결과가 기대값과 같다 | 같음 | 불일치 4건, v1 2 · v2 6 · v3 11 | ☑ 통과 ☐ 수정 | ☑ 통과 ☐ 수정 |
| AC3 | 기능 B 결과가 기대값과 같다 | 같음 | 기한 지남 5건, 기한 당일 T-13 제외, '처리 중' 띄어쓰기도 미답변 | ☑ 통과 ☐ 수정 | ☐ 통과 ☑ 수정(#9) |
| AC4 | 일부러 넣은 함정 행을 사유와 함께 따로 보여 준다 | 같음 | T-12 "비표준 접수일 표기" — 대조·기한 계산에 넣지 않음 | ☑ 통과 ☐ 수정 | ☑ 통과 ☐ 수정 |
| AC5 | 데이터를 외부로 보내지 않는다 | `scripts/`에 외부 주소·외부 전송 코드가 있는지 확인 | 0건 | ☑ 통과 ☐ 수정 | ☑ 통과 ☐ 수정 |
| AC6 | 판단을 확정하지 않는다 | `python scripts/main.py data/team_sample.csv` 끝 줄 | "담당 검토 후 확정" | ☑ 통과 ☐ 수정 | ☑ 통과 ☐ 수정 |

## 4. 경계 입력 (다른 조를 시험할 때 우리가 쓸 것)

| # | 경계 입력 | 예상되는 올바른 동작 |
|---|---|---|
| B1 | 날짜 표기가 섞인 행(예: `2026/11/05`, `2026-11-31`) | 계산에서 빼고 사유와 함께 따로 보여 준다(멈추지 않는다) |
| B2 | 상태 값에 띄어쓰기가 섞인 행(예: `처리 중`) | 같은 상태로 보고 집계한다 |
