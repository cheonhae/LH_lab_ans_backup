## 1. 프로젝트 개요 (왜)

- 해결하려는 문제: 정정공고가 두 번 나온 뒤 민원대장의 적용공고 칸이 접수일과 맞지 않는 행이 섞이고, 미답변 민원 중 답변 기한이 지난 건을 주간 보고 직전에 손으로 찾는다.
- 기대 변화: 명령 한 줄로 ① 적용공고가 기준과 다른 행, ② 답변 기한이 지난 미답변 행을 사유와 함께 받는다.

## 2. 사용자 분석 (누가)

- 주 사용자: 임대공급팀 민원대장 담당자 [가정 — 팀장도 볼 수 있다는 의견은 리뷰 때 다시 봄]
- 쓰는 상황: 주간 민원 보고 초안을 쓰기 전, Claude Code 클라우드 세션에서 실행

## 3. 기능 요구사항 (무엇을)

1. **기능 A — 적용공고 대조**(② 담당): 접수일과 게시일 기준표로 기준 공고를 정해 대장 칸과 대조, 다른 행을 사유와 함께 보여 준다.
2. **기능 B — 답변 기한 확인**(③ 담당): 미답변(접수·처리중) 행의 답변 기한(접수일 + 7일)을 계산해 기준일이 지난 행을 보여 준다.
3. **통합**(① 담당): 두 기능을 한 명령으로 돌려 요약을 보여 주고, 원하면 행별 결과 CSV를 남긴다.
- 공통: 비표준·달력에 없는 접수일은 계산하지 않고 '접수일 확인 필요'로 따로 보여 준다.
- 만들지 않을 것: 화면(HTML), 민원 답변 문구 작성, 주간 보고 초안 자동 수정

## 4. 비기능 요구사항 (어떻게)

- 실제 자료는 넣지 않는다. 가상 표본 데이터로만 시험한다. 데이터를 외부로 보내지 않는다.
- Python 표준 라이브러리만 쓴다. 원본 CSV는 읽기만 한다. 게시일은 기준표 한 곳에서만 읽는다.
- 판단 경계: 적용 공고와 처리 지연 판단은 담당 검토 후 확정한다.

## 5. 성공 지표 (성공)

- 표본 20행을 넣으면 **적용공고 불일치 4건**, **답변 기한 지남 5건**, **접수일 확인 필요 1건**이 행 번호·사유와 함께 나온다.
- 경계: 게시일 당일 접수 = 새 공고, 기한 당일(기한 = 기준일) = 지나지 않음.
- 넣은 검증 절차: 정합 검사(기준표 단일 기준과 대조) + 계산 검산(기한을 손으로 센 값과 대조)
