# 이 레포의 작업 규칙

## 0. 원본 보존
- inputs/ 아래 파일은 읽기만 한다. 고치거나 지우지 않는다.
- 결과는 outputs/m{모듈 번호}/ 에 새 파일로 만든다.
- 커밋 메시지는 사용자가 정한 머리([M1] 등)를 쓴다.

## 팀 규칙
- 팀 레포에는 inputs/ 폴더가 없다. 0절의 원본 보존은 data/의 표본 원본에 같은 뜻으로 적용하고, 결과는 담당 폴더(tools/·scripts/·tests/·docs/)에 만든다.
- 역할별 담당 파일만 수정한다. 담당 파일은 `docs/design.md` 1절 '파일 경계'와 아래 '파일 분담' 표를 따른다.
- 커밋 머리: `[팀-통합]` · `[팀-기능A]` · `[팀-기능B]` · `[팀-검증데이터]`, 공통 문서는 `[팀]`.
- 세션 브랜치에만 푸시한다. main에 직접 푸시하지 않는다.
- PR·이슈는 초안 글만 쓴다. 만들기(세션 화면 Create PR → 초안)·이슈 등록(GitHub 웹)·리뷰 요청 전환·승인·병합은 사람이 한다.
- PR 본문 첫 줄에 `Closes #이슈번호`를 쓴다. 본문은 `.github/pull_request_template.md` 칸을 채운다.
- PR마다 `python tests/run_acceptance.py`를 실행해 결과(통과·실패·미실행)를 본문에 넣는다.
- 자기 PR은 자기가 병합하지 않는다. 자기 PR을 승인하지도 않는다. 리뷰 짝(`docs/project_card.md` 3절)이 승인한 뒤 병합한다. 리뷰 뒤 코드가 바뀌면 다시 승인받는다.
- 병합 순서: ④ 검증·데이터 → ② 기능 A → ③ 기능 B → ① 통합.
- 판단을 확정하지 않는다. 법규 적합·안전 판정·보상·계약금액·당첨·자격은 "담당 검토 후 확정"으로 둔다.

## PRD 이후 작업 규칙 (모든 세션에 적용)
- PRD(`prd/team_prd.md`)와 작업 계획(`docs/team_plan.md`)에 없는 기능, 이번 이슈와 무관한 정리를 하지 않는다. 영향이 작은 선택은 이유 한 줄을 남기고 정한다.
- 작업은 작은 단위로 한다: 구현 → 확인(`tests/run_acceptance.py` 또는 수용 기준표 해당 행) → diff 확인(무관한 변경·디버그 출력·개인정보 없음) → 이번 단위 파일만 커밋 → 세션 브랜치 푸시. 이슈가 끝날 때까지 커밋을 미루지 않는다.
- 실행하지 않은 확인은 "미실행"이라고 쓴다. 확인을 지우거나 기대값을 도구 결과로 바꿔 적어 통과시키지 않는다.
- 자체 검토를 쓸 때는 맨 위에 "AI 자체 검토 — 사람 리뷰 승인이 아님"을 쓴다.
- 개인정보·실제 업무 자료·외부 전송을 넣지 않는다. 데이터는 가상 표본만 쓴다.
- 보고는 실제로 확인한 것만 한다: 바꾼 파일, 확인 결과, 커밋 메시지, 다음 할 일.

### 파일 분담 (작업 계획 때 `docs/design.md` 1절과 같게 채운다)
| 역할 | 담당 파일 |
|---|---|
| ① 통합·화면 | scripts/main.py, README.md, docs/demo_script.md |
| ② 기능 A | scripts/notice_version.py |
| ③ 기능 B | scripts/reply_deadline.py |
| ④ 검증·데이터 | data/team_sample.csv, data/notice_dates.csv, tests/acceptance.md, tests/run_acceptance.py |

### 검증 규칙 (개인 레포 CLAUDE.md 1~3절에서 옮겨 온다)
- 수치·날짜는 기준표 한 곳(`data/notice_dates.csv` — 개인 레포 수치 대장 G-L01·G-L02·G-L13에서 옮김)만 쓴다. 스크립트에 날짜를 적어 넣지 않는다.(개인 3절 정합 규칙)
- 원본 CSV는 수정하지 않는다. 비표준 표기 행은 지우지 않고 '확인 필요'로 따로 보여 준다.(개인 2절 집계 기준)
