# 팀 프로젝트(M6) 진행 기록 — 행정(G) · 진도 도구 `prd-build` 모의 실행

> **모의 실행입니다.** Claude Code 클라우드 세션이 아니라 제작 환경에서 `.claude/skills/prd-build/SKILL.md` 절차(plan → start → step → review → ship)를 따라 산출물을 만들고, 스크립트와 수용 기준은 실제로 실행해 확인했습니다. 세션 화면·소요 시간·초안 PR과 Ready for review 전환·재승인 동작은 D-7 실측(O16·O17·O19)에서 확인합니다.
> 같은 PRD: 팀 PRD는 M5 개인 PRD(`answer/m5/prd/m5_my_prd.md`, 민원대장 적용공고 확인기)를 넓힌 것입니다 — M5의 '다음' 기능(답변 기한)이 기능 B가 됐습니다.
> 이슈·PR 번호는 이 순서로 웹에서 만들었다고 가정한 번호입니다: 이슈 #1~#4, PR #5~#8, 교차 검증 이슈 #9·#10, 수정 PR #11.

## 2. 실제로 실행한 확인

```text
$ python scripts/main.py data/team_sample.csv
전체 20행 · 접수일 확인 필요 1
[적용공고] 대조 19행 · 일치 15 · 불일치 4
[적용공고] 기준 공고별: v1 2 · v2 6 · v3 11
[답변 기한] 기준일 2026-11-13 · 기한 7일 · 미답변 10 · 기한 지남 5
… (행 번호·사유 10줄)
적용 공고와 처리 지연 판단은 담당 검토 후 확정합니다.

$ python tests/run_acceptance.py
AC1~AC6 통과 · 실패 0건 (끝 코드 0)
```

- ④·②만 병합된 상태(③·① 파일 없음)로 따로 돌려 본 결과: AC1·AC2·AC5 통과, AC3·AC4·AC6 '미실행'(이유 표시), 실패 0 — 병합 순서대로 기준이 하나씩 통과로 바뀝니다.
- 교차 검증 이슈 #9 재현: 처리상태 `처리 중` 한 행 → 수정 전 기한 계산에서 빠짐(빈 결과) · 수정 후 '기한 지남'으로 잡힘.

## 3. 만들면서 바로잡은 것

- 처음 통합 도구가 결과를 `outputs/team/`에 썼는데, 팀 규칙(결과는 담당 폴더에)과 맞지 않아 `--out`을 줄 때만 파일을 쓰도록 바꿨습니다(순서 10의 두 번째 커밋).
- 기준 공고별 기대값을 셀 때 게시일 당일 행(T-04·T-10)을 옛 버전으로 세기 쉽습니다. 결정 기록 가정 3(게시일 당일 = 새 공고)을 다시 보고 v1 2 · v2 6 · v3 11로 셌습니다.
